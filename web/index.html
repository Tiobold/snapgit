Review a PR

Someone sent you a snapgit PR. Open it here instead of installing anything. The clock starts when you open it, and its length scales with the size of the change (about half a second per changed line, 15 seconds to an hour). Reject before it runs out, or it merges. A PR nobody opens is simply deleted.

The token stays in this tab's memory and is only ever sent to api.github.com. Opening and rejecting write small refs (refs/snapgit/*) into the repository, exactly like the CLI.

1:00 until merge

The changes are hidden until you open the PR. Opening lights the fuse (longer for bigger changes), and only the first person to open it gets to read it.

⏳ Disappearing branches

snapgit snap wip/idea --ttl 2h puts a real git branch on a timer. When it runs out, it is gone, locally and on the remote.

🚫 One button

A PR can only be rejected. Open it and a fuse is lit, sized to the change: when it burns out, it merges into main unless you said no. Never opened? It is deleted, not merged.

🔀 Merge by neglect

No approvals, no LGTM. Silence is consent. Your sender's snapgit does the merge with plain git.

😬 CI shame

Checks run before a PR is sent and again before it merges. Fail, and the authors (human or agent) are shamed and the branch self-destructs.

📊 Metrics, by team

Did review get faster? How many PRs did nobody open? Do agents fail CI more than people? See the dashboard. Never per person; groups under three are hidden.

🤖 Built for agents

snapgit init --agent teaches Claude Code and friends the rules, and every command they need speaks --json. Fail CI and the agent is shamed like anyone else.

🔌 On real GitHub PRs

The GitHub Action puts ordinary pull requests on the same clock, with a bot comment for state and nothing to host. snapgit init --workflow installs it.

🖥️ No servers

This page talks straight to GitHub. PRs are refs in your own repository, so there is nothing of ours to go down.
