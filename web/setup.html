👻 snapgit

Setup: a token, or your own copy

The web pages have no server. They talk straight from your browser to GitHub, so they need a token to write, and you can host them anywhere, including your own GitHub repository.

Getting a GitHub token

You need one to open or reject a PR, and for the metrics dashboard on a private repository. Reading a public repository needs none.

  1. Open github.com/settings/personal-access-tokens/new (Settings, Developer settings, Personal access tokens, Fine-grained tokens, Generate new token).
  2. Name it snapgit and choose a short expiry (7 to 30 days is plenty).
  3. Resource owner: the user or organization that owns the repository. Repository access: Only select repositories, then pick just the repository you review in.
  4. Under Repository permissions set Contents: Read and write to open or reject PRs (snapgit stores them as small refs, refs/snapgit/*). For the dashboard alone, Contents: Read-only and Pull requests: Read-only are enough.
  5. Generate the token, copy it (GitHub shows it once) and paste it into the page. It stays in that tab's memory and is only ever sent to api.github.com. Close the tab and it is gone.

Organization repository and the token is refused? The organization may require approval for fine-grained tokens (ask an owner), or use a classic token: Settings, Developer settings, Tokens (classic), scope repo (or public_repo for public repositories), then Configure SSO and authorize it if your organization uses SSO.

Why a token at all? A web page cannot sign you in to GitHub without a server somewhere. snapgit has none on purpose, so you hold the key, and it only ever lives in your browser.

Hosting the web pages in your own GitHub repository

The site is plain static files (the web/ folder), so GitHub Pages can serve it. Nothing of ours is involved.

  1. Fork Tiobold/snapgit (or copy its web/ folder and .github/workflows/pages.yml into any repository you own).
  2. In your fork: Settings, Pages, and set Source to GitHub Actions.
  3. Open the Actions tab, enable workflows if GitHub asks, choose Deploy web to GitHub Pages and press Run workflow.
  4. A minute later your site is at https://YOUR-NAME.github.io/snapgit/. Add ?repo=owner/name to the metrics address to prefill the repository.

Private repositories on a private Pages site work the same way (Pages visibility is a Settings option on paid plans). A custom domain goes under Settings, Pages.

Other hosts

Vercel: import the repository and set the Root Directory to web. Anywhere else: upload the web/ folder to any static host, or run it locally with npx serve web. It has no build step.

Hosts that cannot send headers (GitHub Pages included) rely on the content security policy each page carries in a meta tag, so the pages still only talk to api.github.com.

Adding "Sign in with GitHub" (host operators)

Optional, and the one piece that needs a server: three tiny functions in web/api/ (Vercel runs them as is) that swap GitHub's sign-in code for a token, because that swap needs a secret. Nothing is stored. Without it the pages just keep the token field, and the button never appears (GitHub Pages included).

  1. Register a GitHub App: Settings, Developer settings, GitHub Apps, New GitHub App. Callback URL https://YOUR-SITE/api/auth/callback. Untick Webhook. Keep Expire user authorization tokens on. Repository permissions: Contents: Read and write, Pull requests: Read-only.
  2. Generate a client secret. In your host's settings add the environment variables GITHUB_CLIENT_ID and GITHUB_CLIENT_SECRET (and PUBLIC_URL if you serve it from a custom domain), then redeploy.
  3. Each team installs the App on the repositories they review in (the App's page, Install App). Sign-in tokens only reach repositories where the App is installed and the person has access, they expire after 8 hours, and they are handed to the page in the URL fragment, which is never sent to any server and is removed from the address bar at once.

Why an App and not an OAuth app? An OAuth app can only ask for the broad repo scope (every repository you can reach). An App gets just Contents and Pull requests, on the repositories it is installed on.

Prefer no web page at all?

The CLI needs no token, because it uses your own git credentials: snapgit pr open <id> -r origin. And on real GitHub PRs, the Action works with the workflow's built-in token: snapgit init --workflow.
